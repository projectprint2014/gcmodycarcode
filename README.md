# نظام تفعيل الضمان — نسخة بداية قابلة للنشر على Cloudflare

واجهة عربية RTL لتفعيل الضمان، ولوحة إدارة متعددة الأدوار، واستيراد Excel، مع تخزين دائم في Cloudflare D1.

## مهم قبل الاستخدام الحقيقي
هذه حزمة بداية عملية وليست خدمة منشورة أو إعدادًا تم اختباره على حسابك. لا تضع بيانات العملاء الحقيقية قبل إكمال خطوات النشر والاختبار أدناه. احتفظ دائمًا بنسخة احتياطية من Excel وقاعدة البيانات.

## المزايا
- واجهة عربية للعملاء.
- استيراد Excel `.xlsx` أو `.xls` من لوحة الإدارة (يقرأ العمود الأول افتراضيًا، أو عمود اسمه `code` / `كود الضمان`).
- تخزين بصمة SHA-256 للكود بدل تخزين الكود الخام في قاعدة البيانات.
- تفعيل ذري داخل معاملة SQL؛ لا يمكن تفعيل الكود مرتين.
- أدوار: `owner` (مالك)، `admin` (مدير)، `viewer` (قراءة فقط).
- جلسات في Cookie من نوع HttpOnly وSecure وSameSite=Strict.
- تغيير كلمة المرور، وإضافة مستخدمين من المالك.
- سجل التفعيل والتصدير CSV.
- لا توجد رسوم اشتراك لازمة للبدء ضمن حدود الخطط المجانية، لكن حدود الخدمات وشروطها قابلة للتغيير.

## هيكل الملفات
- `public/index.html` الواجهة.
- `src/worker.js` واجهة API والخادم.
- `schema.sql` جداول D1.
- `wrangler.toml` إعداد Cloudflare.

## نشر مختصر
1. أنشئ حساب GitHub وارفع ملفات هذا المشروع إلى مستودع خاص (Private).
2. أنشئ حساب Cloudflare.
3. ثبّت Node.js وWrangler على جهازك:
   ```bash
   npm install -g wrangler
   wrangler login
   ```
4. أنشئ قاعدة البيانات:
   ```bash
   wrangler d1 create warranty-db
   ```
   انسخ `database_id` الناتج وضعه مكان `REPLACE_WITH_DATABASE_ID` في `wrangler.toml`.
5. نفّذ الجداول:
   ```bash
   wrangler d1 execute warranty-db --remote --file=schema.sql
   ```
6. عيّن سر التهيئة الأولية (قيمة طويلة عشوائية، لا تشاركها):
   ```bash
   wrangler secret put SETUP_TOKEN
   ```
7. انشر التطبيق:
   ```bash
   wrangler deploy
   ```
   سيعطيك Cloudflare رابطًا. الواجهة والـ API على نفس النطاق لتعمل ملفات الجلسات بشكل صحيح.
8. افتح الرابط وأكمل تهيئة المالك عبر الواجهة. استخدم `SETUP_TOKEN` الذي عيّنته، وأنشئ كلمة مرور طويلة وفريدة.
9. بعد إنشاء المالك، احذف سر التهيئة من إعدادات Worker أو غيّره فورًا. لا تترك رمز التهيئة متاحًا.

## رفع المشروع إلى GitHub
ارفع ملفات المصدر إلى مستودع Private، لكن لا ترفع كلمات المرور أو الرموز السرية أو ملف `.dev.vars`. لا تضع أكواد الضمان الفعلية في المستودع.

## صيغة ملف Excel
ضع الأكواد في عمود واحد. الأفضل تسمية عنوان العمود `code` أو `كود الضمان`. الأكواد تُعامل كنصوص؛ لا تستخدم تنسيقًا يحذف أصفار البداية. الأكواد المكررة تُتجاهل أثناء الاستيراد ويظهر عددها.

## الأدوار
- `owner`: إضافة مستخدمين، استيراد الأكواد، عرض السجلات، تغيير كلمة المرور.
- `admin`: استيراد الأكواد وعرض السجلات.
- `viewer`: عرض السجلات فقط.
- الحسابات لا يمكن تسجيلها ذاتيًا من صفحة العميل.

## اختبارات ضرورية قبل إطلاق الرابط للعملاء
- كود صحيح يتفعل مرة واحدة فقط.
- تجربة تفعيل الكود نفسه من نافذتين أو جهازين بالتزامن.
- كود غير موجود.
- استيراد ملف فيه تكرارات وصفوف فارغة.
- التأكد أن `viewer` لا يستطيع الاستيراد أو إضافة المستخدمين.
- استخدام HTTPS، وتفعيل المصادقة الثنائية لحساب Cloudflare وGitHub.
- تنزيل نسخة احتياطية دورية من D1، والاحتفاظ بملف Excel الأصلي.
- ضع سياسة خصوصية إذا جمعت اسم العميل أو هاتفه. النسخة الحالية لا تجمعهما.

## تنبيه
هذا مشروع أولي قابل للتطوير، وليس بديلًا عن مراجعة أمنية مستقلة. لا تستخدم نفس كلمة مرور GitHub/Cloudflare ككلمة مرور لوحة المدير. راجع الحدود المجانية الحالية لدى Cloudflare قبل الإطلاق.
